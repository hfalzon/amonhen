## Windows project discovery

Fixes divergent project lists between a normal terminal and a packaged desktop
agent. Windows MSIX AppData virtualization could give each process a different
`projects.json` at the same apparent path.

Windows project metadata now lives in `%USERPROFILE%\.amonhen\projects.json`.
After upgrading, run this once in a normal host terminal:

```text
amonhen storage migrate
```

Migration leaves the old registry and all existing OS credentials unchanged.
For a new installation, use `amonhen storage init`. Upgrade every Amon Hen
executable; older versions continue reading the legacy file.

Lookups read the authoritative index afresh. Missing, invalid, inaccessible or
redirected stores fail explicitly. Mutations use an interprocess lock and atomic
metadata replacement. `project rename -N old --new-name new` preserves the saved
credential. The Windows installer also rejects redirected executable paths.

## Verification and support limits

The affected Windows desktop passed real host/MXC bidirectional add, rename and
delete checks without restarting clients. MXC and both legacy sandbox modes
also passed paired fixture freshness checks. All three existing credentials
remained retrievable without re-entry under approved execution. Tests, vet,
workflow linting and all five release cross-builds passed locally.

Direct Credential Manager access is denied in the tested MXC sandbox; token
operations there require approved host execution. The legacy elevated sandbox
tested the build from the workspace; its AppData installation path was denied
at process startup. No permissions were weakened to bypass either restriction.

This release does not establish universal sandbox or credential-store support.
Dedicated live BWS authentication, macOS/Linux credential-store runtime tests,
fresh full agent sessions, sign-out/sign-in, reboot and unauthorized-identity
acceptance remain outstanding. Amon Lhaw Go integration was checked with a
synthetic credential and controlled BWS child, not a live BWS request.

See [the investigation record](https://github.com/hfalzon/amonhen/blob/v0.4.0/docs/sandbox-investigation.md)
for environment versions, evidence, migration behavior and remaining checks.
